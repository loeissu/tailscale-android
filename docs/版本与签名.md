# Tailscale Android 汉化版 版本号与签名（阶段五）

> 本文件属于同步保留清单。

## 1. 版本号（与上游正式版一致）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 展示版本（About / 设置页） | `1.102.2` | `AppVersion.Short()` 取 `versionName` 破折号前段 |
| versionName（BuildConfig.VERSION_NAME） | `1.102.2-t<hash>-g<hash>` | 由 `mkversion` 从 `go.mod` 的 `tailscale.com v1.102.2` + 本仓 HEAD 生成 |

| 汉化版 Release tag | `v1.102.2-zh` | semver 兼容（`v` 前缀 + `1.102.2` + 预发布标识 `-zh`） |

### versionCode 推导公式（本仓库实情）

本仓库**不使用**"1.4.1 → 10401"式公式。上游刻意采用墙钟公式，并在 `android/build.gradle` 顶部注释写明，禁止改为版本派生值：

```
versionCode = minutes_since_unix_epoch × 10        # 每次发版由 make bump-version-code 更新
末位保留：手机/平板=0，AndroidTV=+1
```

- 当前值：`297646690`。
- 汉化版策略：**沿用上游每次正式发版时的 versionCode 原值**。
  - 与上游正式版一致（满足"版本号与上游正式版一致"）；
  - 随上游发版单调递增（时间轴全局递增），保证汉化版覆盖安装链不断；
  - 同一上游版本重复构建时 versionCode 不变，配合固定签名仍可 `adb install -r` 覆盖安装。
- 不需要汉化 Fork 自行推导额外 versionCode。

## 2. 签名

采用**方案 A：提交固定 keystore（社区 fork 推荐）**。

| 项 | 值 |
| --- | --- |
| keystore | `android/zh-release.jks`（已提交仓库） |
| 别名 | `tailscale-zh` |
| 证书 SHA-256 | `D2:32:BE:67:21:87:9E:73:6B:BF:EA:40:DD:15:7F:AA:85:9F:E6:75:F0:28:D0:92:A7:7E:DE:0D:2C:4E:73:20` |
| 口令 | 见 `android/keystore.properties`（公开重建密钥，非保密） |
| 签名工具 | `apksigner`（Android SDK build-tools 36.0.0），v1+v2+v3 签名 |
| 覆盖安装链 | 汉化版 → 汉化版 ✅（同签名）；官方版 → 汉化版 ❌（签名不同） |

### 为什么选 A 不选 B
- **方案 B（GitHub Secrets）**：更安全，但只有原仓库持有者能构建；Fork 后签名不一致，社区无法复现、覆盖安装链断裂。
- **方案 A（提交 keystore）**：任何人可重建同签名产物，汉化版→汉化版覆盖安装链不断；代价是"密钥"公开，任何人也都能冒名构建（对社区 fork 可接受，与官方版权方无关）。

### 安装说明（写给用户）
- 官方版 → 汉化版：**必须卸载官方版**再安装（包名同为 `com.tailscale.ipn`，签名不同，覆盖安装会被系统拒绝）。
- 汉化版 → 汉化版：直接覆盖安装，配置与登录状态保留。

## 3. 签名命令（CI 内执行，参考）

```bash
BUILD_TOOLS="$ANDROID_HOME/build-tools/36.0.0"
# 1) 未签名 release APK（android/build/outputs/apk/release/android-release-unsigned.apk）
# 2) zipalign
"$BUILD_TOOLS/zipalign" -f -p 4 in.apk aligned.apk
# 3) apksigner 签名
"$BUILD_TOOLS/apksigner" sign \
  --ks android/zh-release.jks --ks-pass pass:"$(jq -r .storePassword < /dev/stdin)" \
  --ks-key-alias tailscale-zh --key-pass pass:"$(jq -r .keyPassword < /dev/stdin)" \
  --out tailscale-android-zh.apk aligned.apk
# 4) 校验
"$BUILD_TOOLS/apksigner" verify --print-certs tailscale-android-zh.apk
```
（工作流中口令从 `android/keystore.properties` 读取。）

## 4. semver 兼容性验证

- 上游 `1.102.2-t6cac91817-g8c99ed49d`：`AppVersion.Short()` 取破折号前段 → `1.102.2`（版本比较逻辑只识别语义版本）。
- 汉化 tag `v1.102.2-zh`：符合 semver（`major.minor.patch` + 预发布 `-zh`），`v` 前缀按 semver 规范允许。
- 应用内版本解析（`TSLog` 取第 2 段作 API 级别判定）不受 `-zh` 影响。
- 因此使用 `v{版本}-zh` 标签即可，无需退化为"v{版本} + Release name 区分"。
