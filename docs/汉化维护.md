# Tailscale Android 汉化版维护手册（阶段四/七）

> 本文件属于同步保留清单（见 `tools/retain-list.json`），同步时从 main 恢复。

## 1. 架构

```
tools/zh_cn.json          翻译词典：资源 key -> 简体中文（唯一事实来源）
tools/extract-zh.py       从英文基准提取可翻译条目并更新词典骨架
tools/apply-zh.py         依据词典生成 android/src/main/res/values-zh-rCN/*.xml
                          --check 模式校验：剩余未翻译=0 才 PASS，失败退出码非 0
tools/sync-upstream.py    上游同步脚本（阶段四）
tools/retain-list.json    同步保留清单（机器可读）
tools/zh-last-release.txt 上次同步的上游 Release tag
android/src/main/res/values-zh-rCN/   生成的简体中文资源（勿手改）
android/src/main/res/font/            Noto Sans SC（SIL OFL 1.1，见 docs/OFL-NotoSansSC.txt）
android/zh-release.jks + keystore.properties   汉化版签名（方案 A）
```

- `.github/workflows/sync-upstream.yml`、`.github/workflows/release.yml`、`.github/workflows/zh-check.yml`

### 与上游共享的文件（上游改动时用 three-way 合并，不用覆盖）

## 3. 补充翻译（新增字符串时）

1. 上游发布新版本含新字符串，`tools/sync-upstream.py --check` 会因 `[missed]` 失败。
2. 运行 `python tools/extract-zh.py` 生成含新 key 的词典骨架（新 key 为空串）。
3. 打开 `tools/zh_cn.json` 补全译文（保持 `%s`/`%d`/`%1$s` 等占位符原样）。
4. `python tools/apply-zh.py --check` 直到输出 `PASS (剩余=0)`。
5. 重新触发同步或提交后由 `zh-check.yml` 把关。

专有名词（Tailscale / Mullvad / Taildrop / VPN / DNS / URL / Ping / CIDR / Headscale / GitHub / OpenGL / FPS）无需翻译，词典 key 存在即视为已翻译，不会误判。

## 4. 上游同步流程（阶段四）

工作流：`.github/workflows/sync-upstream.yml`（手动触发 + 每日定时）。
脚本：`tools/sync-upstream.py`。

```
检测新 Release -> checkout 上游 Tag -> 恢复保留清单 -> apply 词典
-> check(剩余=0) -> 更新版本号(版本与签名.md 中的规则) -> 推送 main -> 构建 -> 发布
```

- **last-release 更新时机：模式 A（简单模式，默认）**
  - `tools/zh-last-release.txt` 在 sync 推送 main **前**更新。
  - 若 release 构建失败：人工重跑 `.github/workflows/release.yml`，不阻塞下次同步。
  - 严格模式 B：构建发布成功后再更新（repository_dispatch 回调），本仓库未启用，如需启用按脚本 `--mode B` 说明实现。
- **失败语义**：任意一步失败 → 远程 `main` 不变、不发布；日志由 GitHub Actions 保留；可手动 Run workflow 重试。
- **无新版跳过**：上次同步 == 上游最新 Release 时，输出"无新版跳过"并正常退出（已实测通过）。

## 5. 版本号与 versionCode（阶段五）

详见 `docs/版本与签名.md`。要点：
- 展示版本 = 上游 VERSION_SHORT（如 `1.102.2`），与上游正式版一致。
- versionCode 沿用上游墙钟值（`minutes_since_epoch × 10`，当前 `297646690`），随上游发版单调递增。
- 汉化版 tag：`v{短版本}-zh`（semver 兼容）。

## 6. App 内更新（阶段七，结论 N/A）

已核查：本应用**没有** `githubOwner`/`githubRepo` 指向 GitHub Release 的更新下载逻辑。
更新提示由 **Tailscale 控制平面**下发（`MapResponse.ClientVersion` → health → "Update Available"），
点击后跳转安装源（Play 商店 / F-Droid）。因此没有可改为 Fork 的 GitHub 下载地址，本 Fork 不提供"App 内检查汉化版更新"，
用户通过本仓库 Release 页面获取新汉化版。版本比较逻辑（`AppVersion.Short()` / `TSLog`）只解析语义版本，不会把汉化版与上游版本混淆。

## 7. 发布（阶段六）

- 打 `v{短版本}-zh` tag 即触发 `.github/workflows/release.yml`：编译、单测、apksigner 签名、SHA256、创建/更新 GitHub Release（`--clobber` 覆盖同版本资产，不产生 `-2/-3`）。
- 官方版（Tailscale 官方签名）→ 汉化版：**必须卸载**官方版再安装（包名相同、签名不同）。
- 汉化版 → 汉化版（新版覆盖旧版）：签名一致（方案 A 固定 keystore），支持覆盖安装，数据保留。
