# Tailscale Android 汉化可行性分析

> 本文件为阶段一调研成果（一次性交付，不进入同步保留清单）。
> 上游仓库：https://github.com/tailscale/tailscale-android
> Fork：https://github.com/loeissu/tailscale-android
> 目标平台：**仅 Android**（结论见下文）
> 调研基准版本：上游 Release tag `1.102.2-t6cac91817-g8c99ed49d`（VERSION_SHORT = 1.102.2）

---

## 1. UI 技术栈

| 项目 | 结论 |
| --- | --- |
| UI 框架 | Jetpack Compose（Material3 1.3.0，Compose 1.7.x），单 Activity + Navigation Compose |
| 语言 | Kotlin 1.9.22 |
| 界面入口 | `MainActivity`（`com.tailscale.ipn`） |
| 主题 | `ui/theme/Theme.kt`，Material3 `Typography` 使用**系统默认字体**（`FontFamily.Default`），未自定义字体族 |
| 布局方式 | 全部 Compose 声明式布局，无 XML 布局文件 |

## 2. UI 文本位置

| 位置 | 内容 | 数量 | 是否汉化范围内 |
| --- | --- | --- | --- |
| `android/src/main/res/values/strings.xml` | 全部用户可见 UI 文案（通用、设置、主界面、退出节点、Tailnet 锁、DNS、MDM 限制描述、分享、弹窗标题、引导页、通知渠道、隧道拆分、Mullvad、子网路由、硬件证明等） | 约 210 个可翻译条目（另有约 10 个 `translatable="false"`） | ✅ 是 |
| `android/src/main/res/values/string-arrays.xml` | 3 个可翻译数组：`hidden_network_devices_labels`、`always_never_userdecides_labels`、`show_hide_labels` | 3 个数组共 8 项 | ✅ 是 |
| Compose 代码硬编码 | 仅 1 处 `Text(...)`：`MullvadExitNodePicker.kt` 中国家旗帜 + 国家名（动态内容，非静态文案） | 1 | ❌ 否（动态内容） |
| `mdm/MDMSettings.kt` | MDM 策略的描述字符串（Kotlin 硬编码），仅用于"内部调试选项 / MDM 调试视图"及 Go 侧 syspolicy 键 | 约 25 个 | ❌ 否（管理员/调试向，非最终用户 UI） |

**结论**：本应用的所有最终用户可见文案都集中在 Android 标准字符串资源中，没有侵入式硬编码，汉化路径非常干净。

## 3. i18n 现状

- 仓库内**没有**任何 `values-zh*` 本地化目录，只有默认 `values/`。
- 没有使用第三方 i18n 框架，全部是 Android 原生 `res/values` 字符串资源。
- `translatable="false"` 用于：`app_name`、`tile_name`、`empty`、`template`、`placeholder`、`custom_control_placeholder`、`mullvad_exit_nodes`、`hidden_network_devices`、`always_never_userdecides`、`show_hide` 等（机器可读键 / 品牌名 / 占位符），**不翻译**。
- 汉化采用 Android 原生机制：新增 `values-zh-rCN/strings.xml` 与 `values-zh-rCN/string-arrays.xml`，系统语言为简体中文时自动加载。默认英文资源保持与上游完全一致 → 上游同步时字符串文件**零冲突**。

## 4. 中文字体支持

- minSdk = 26（Android 8.0）。Android 8.0+ 系统内置 **Noto Sans CJK SC**（含简体中文全套字形），并作为所有字体族的系统级 fallback。
- 本应用 Compose 主题未覆盖 `FontFamily`，Text 默认走系统字体 → 中文在**任何** Android 8+ 设备上都能正确渲染，不会出现方框/乱码。
- 为满足"阶段三：字体"要求并彻底规避极少数定制 ROM 缺字风险，将随包捆绑 **Noto Sans SC**（SIL OFL 1.1 开源字体）并配置为 Compose 字体族（含 fallback），见阶段三。

## 5. 构建系统

| 项目 | 结论 |
| --- | --- |
| 构建驱动 | `Makefile`（`make tailscale-debug.apk` / `make release`） |
| 原生库 | `tool/go`（按 `go.toolchain.rev` 下载 Tailscale 定制 Go 工具链）→ gomobile bind 生成 `android/libs/libtailscale.aar`（Go 引擎，wireguard/netstack） |
| 版本生成 | `make tailscale.version` 由 `tailscale.com/cmd/mkversion` 从 `go.mod` 的 `tailscale.com` 依赖版本 + 本仓 git HEAD 生成 |
| Gradle | AGP 8.13.0、Kotlin 1.9.22、Gradle 封装在 `android/gradle/wrapper`；`androidApiLevel=36`、`androidBuildToolsVersion=36.0.0`、NDK `23.1.7779620` |
| JDK | 必须 JDK 17（sourceCompatibility/targetCompatibility/jvmTarget = 17） |
| 测试 | `make go-test`（Go）+ `make test`（Gradle 单元测试）+ ktfmt 格式检查 |

## 6. CI 现状

- `.github/workflows/android.yml`：ubuntu-latest，Go（读 go.mod）+ Java 17，`make clean && make fmt-check && make go-test && make tailscale-debug.apk && make test`。
- `.github/workflows/integration-test.yml`：Docker + Android 模拟器（`ANDROID_INTEGRATION_DOCKER_IMAGE`），跑 Go 集成测试。
- `.github/workflows/go_mod_tidy.yml`、`license-headers.yml`：常规检查。
- 上游**没有**自动发布 GitHub Release 的工作流（Release 由 Tailscale 内部 CI 产出）。

## 7. 版本号与 versionCode（关键事实）

- `versionName` = `build.gradle` 中 `versionName getVersionProperty("VERSION_LONG")`。
- `VERSION_LONG` 由 `mkversion` 生成，格式 `1.102.2-t<tailscale-hash>-g<android-commit>`；应用内展示时使用 `AppVersion.Short()` 只显示 `1.102.2`。
- **版本号与上游正式版一致** = VERSION_SHORT 与上游相同（由 `go.mod` 的 `tailscale.com v1.102.2` 决定），展示版本 = `1.102.2`。
- `versionCode`：**不是**"1.4.1 → 10401"这类公式，而是上游刻意采用的**墙钟公式**：`minutes_since_epoch × 10`（当前值 `297646690`），每次发版由 `make bump-version-code` 递增，末位保留给 TV 变体（手机=0）。
  → 汉化版沿用上游每次发版时的 versionCode 原值即可保证"与上游正式版一致"且单调递增（覆盖安装链可用），详见阶段五文档。

## 8. 签名现状

- 上游 release：`make release` 用 `JKS_PATH`/`JKS_PASSWORD` 环境变量对 AAB 做 `jarsigner`；`tailscale.jks` 在 `.gitignore` 中，**不**提交。
- 本地 debug：Gradle 自动生成 `~/.android/debug.keystore`（每台机器/每次 CI 运行都不同）。
- 汉化 Fork 采用**方案 A：提交固定 keystore**（社区 fork 推荐），使任意人可重建同签名产物、汉化版↔汉化版覆盖安装链不断。

## 9. App 内更新（关键事实）

- 已核查 Android 源码：**不存在** `githubOwner`/`githubRepo` 之类指向 GitHub Release 的更新下载逻辑。
- 更新机制是**控制平面驱动**：Go 后端（`tailscale.com/ipn/ipnlocal`）在 `MapResponse` 收到 `ClientVersion`（含 `LatestVersion`）后写入 health，客户端据此显示"Update Available"并跳转安装源（Play 商店 / F-Droid）。
- 因此"阶段七：App 内更新 githubOwner/githubRepo 改为 Fork"在本仓库**不适用（N/A）**。本 Fork 会：
  1) 在汉化维护文档中说明该机制，避免后续误改；
  2) 验证版本比较逻辑不会把汉化版（1.102.2）误判为低于官方（1.102.2）或误识别上游版本。

## 10. 各平台支持情况与成功概率

| 平台 | 支持情况 | 判断 | 依据 |
| --- | --- | --- | --- |
| **Android** | ✅ 唯一目标平台 | 成功概率 **高** | 全部 UI 文案在字符串资源中，无硬编码；构建链路（gomobile AAR + Gradle）与上游 CI 完全一致，在 GitHub Actions 上可行；字体/覆盖安装/版本号均有明确方案 |
| Windows | ❌ 不支持 | 不适用 | 本仓库是 Android 应用仓库（`tailscale-android`），没有任何 Windows 桌面产物/构建目标；Windows 仅作为本地开发宿主（本调研环境即 Windows） |
| Linux | ❌ 无独立目标 | 不适用 | 仓库不产出 Linux 桌面程序；Linux 仅作为 GitHub Actions 的**构建宿主**（ubuntu-latest），最终产物是 Android APK/AAB。因此验收表"编译产物 + 启动验证"落在 Android 上 |

## 11. 风险与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 本地无法构建 | 本机无 Android SDK、JDK 仅 1.8、无 Go 1.26 工具链 | 构建/验证全部放到 GitHub Actions（与上游 CI 同构）；本地只做纯文本/脚本层改动与工具单测 |
| gomobile 构建时间长/依赖外网 | libtailscale AAR 需下载 Tailscale 定制 Go 工具链 + 编译 | 沿用上游 Makefile 流程；Release 工作流独立、幂等，失败可重跑 |
| 官方版→汉化版覆盖安装 | 签名不同 | 文档明示：需先卸载官方版再安装汉化版（包名保持 `com.tailscale.ipn`，数据不迁移） |
| 汉化版→汉化版覆盖安装 | 签名必须稳定 | 提交固定 keystore（方案 A），Release 全部用该 keystore 签名 |
| 中文长文本裁切 | 中文比英文短文本更长 | Compose 默认自动换行；对长文案检查是否显式 `maxLines`/固定高度，必要时调整（阶段八）；模拟器截图验证 |
| 上游同步冲突 | 字符串/资源文件被上游修改 | 默认英文资源与上游零差异；`values-zh-rCN` 为纯新增文件；保留清单 + 三路合并策略见阶段四 |
| `translatable="false"` 误翻 | 机器可读键、品牌名不能翻 | check 工具按属性跳过；白名单兜底 |

## 12. 结论

- **可行**。本应用是纯 Compose + 字符串资源的 Android 应用，汉化工程量小、风险低。
- 唯一目标是 **Android**；Windows/Linux 无对应产物（Windows/Linux 仅作构建宿主），已在验收表标注"不适用"及理由。
- 汉化策略：`values-zh-rCN` 原生本地化 + `tools/zh_cn.json` 词典 + `extract-zh.py`/`apply-zh.py` 可复现管线 + 固定 keystore 签名 + GitHub Actions 自动构建发布。
